# 機能要件

最終更新: 2026-11-07

**目的: 機能の実装漏れを防ぐ。** 実装時はこの ID を参照する。画面の見た目は [UI/UX設計](../02-design/ui-ux-design.md)、データの持ち方は [DB設計](../02-design/database-design.md) を見る。

ID の体系: `FR-A`=認証 / `FR-H`=世帯 / `FR-T`=記録 / `FR-L`=一覧と集計 / `FR-C`=カテゴリ / `FR-X`=共通

## 1. 機能一覧

### FR-A 認証

**メールアドレス + パスワードを主とし、マジックリンクは「パスワードを忘れたとき」の導線として残す**（→ [ADR-0006](../05-decisions/ADR-0006-email-password-auth.md)）。

| ID | 要件 | 優先 | 画面 |
| --- | --- | --- | --- |
| FR-A1 | メールアドレスとパスワードでログインできる | 必須 | `/login` |
| FR-A2 | メールアドレスとパスワードで新規登録できる。確認メールが 1 通届き、リンクを開くと有効化される | 必須 | `/signup` |
| FR-A3 | パスワードは 8 文字以上。新規登録時は確認入力を求める | 必須 | `/signup` |
| FR-A4 | ログイン状態は Cookie で保持され、アプリを開き直してもログインしたままになる | 必須 | 全体 |
| FR-A5 | 未ログインで認証後の画面を開こうとした場合、ログイン画面へ遷移する | 必須 | 全体 |
| FR-A6 | パスワードを忘れた場合、ログイン用のリンクをメールで受け取れる | 必須 | `/login/link` |
| FR-A7 | ログアウトできる | 必須 | `/settings` |
| FR-A8 | ログイン失敗時、メールアドレスとパスワードのどちらが違うかを示さない | 必須 | `/login` |
| FR-A9 | 新規登録・リンク送信の結果から、メールアドレスが登録済みかどうかを判別できない | 必須 | `/signup`, `/login/link` |
| FR-A10 | ログイン後にパスワードを変更できる | 必須 | `/settings` |
| FR-A11 | メールの送信制限に達した場合は、その旨を表示する（黙って失敗させない） | 必須 | `/signup`, `/login/link` |
| FR-A12 | 登録済みのアドレスでは確認メールが届かないことを `/signup` で案内する | 必須 | `/signup` |
| FR-A13 | 確認メールを再送できる。未確認のままログインを試した場合も自動で再送される | 必須 | `/login/verify`, `/login` |

**マジックリンクで新規登録はできない**（`shouldCreateUser: false`）。アカウントの作成は `/signup` のパスワード経由に限る。

### FR-R 定期支出

| ID | 要件 | 優先 | 画面 |
| --- | --- | --- | --- |
| FR-R1 | 記録に「毎月くり返す」の印を付けられる | 任意 | `/new`, `/transactions/[id]` |
| FR-R2 | 先月の印つき記録のうち今月に無いものを、まとめて登録できる | 任意 | `/` |
| FR-R3 | 写した記録にも印が付く（翌月も候補に出る） | 任意 | — |

- 日付は先月と同じ日。**その月に無い日は末日に寄せる**（1/31 → 2/28）
- **同じカテゴリ・同じ金額が今月に既にあれば写さない**（二重登録を防ぐ）
- **自動実行はしない。** 押すまで何も起きない。Cron 化はデプロイ後（[ADR-0011](../05-decisions/ADR-0011-tier1-and-recurring.md)）

## 2. 業務ルール

機能をまたいで常に成り立つ規則。実装時にどこか 1 箇所で破るとデータが壊れるもの。

| # | ルール | 担保する場所 |
| --- | --- | --- |
| BR-1 | 1 ユーザーは最大 1 つの世帯に所属する | `Profile.householdId` が単一値 / 世帯作成時の所属チェック |
| BR-2 | 金額は 1 以上の整数（円）。符号を持たない。向きは `kind` で表す | DB の CHECK 制約 / 入力検証 / Server Action の検証 |
| BR-3 | 同じ世帯のメンバーは、誰が作った記録でも編集・削除できる | DAL（世帯 ID のみで絞り、作成者は見ない） |
| BR-4 | 自分以外のメンバーの表示名は変更できない | DAL（自分の `Profile.id` のみを対象にする） |
| BR-5 | 記録の `householdId` は、サーバーが認証情報から決める。クライアントの値を使わない | DAL（`requireMember()` から埋める。引数で受け取らない） |
| BR-6 | `createdById` は常にログイン中のユーザー。変更できない | DAL（`requireMember()` から埋める。更新時は触らない） |
| BR-7 | カテゴリは削除せず非表示にする。既存の記録の表示を壊さない | `archived` 列 / UI に削除操作を作らない |
| BR-8 | カテゴリ名は世帯 × 種別の中で一意 | DB の一意制約 `(householdId, kind, name)` |
| BR-9 | 招待コードは全世帯で一意。6 桁の英数字（大文字） | DB の一意制約 + CHECK 制約 / 生成時の衝突チェック |
| BR-10 | 日付は時刻を持たない。タイムゾーンによって日が動いてはならない | `date` 型 / 文字列 `"YYYY-MM-DD"` で受け渡す |
| BR-11 | メンバーが世帯から外れても、その人の記録は残る | `paid_by` の `on delete set null` |
| BR-12 | 他の世帯のデータは、いかなる操作でも取得・変更できない | **DAL のすべてのクエリの `householdId` 条件 + 認可テスト**（[ADR-0005](../05-decisions/ADR-0005-authorization-in-app-layer.md)） |

## 3. 入力項目の仕様

### 3.1 記録（`/new`, `/transactions/[id]`）

| 項目 | 必須 | 型・制約 | 既定値 | 検証エラー時の文言 |
| --- | --- | --- | --- | --- |
| 種別 | ○ | `expense` / `income` | `expense` | — |
| 金額 | ○ | 整数、1 以上 9,999,999 以下 | 空 | 「金額を入力してください」/「金額が大きすぎます」 |
| 日付 | ○ | `YYYY-MM-DD` | 当日 | 「日付の形式が正しくありません」 |
| カテゴリ | — | 自分の世帯の、種別が一致する、非表示でないカテゴリ | 未選択 | 「選択できないカテゴリです」 |
| 支払った人 | — | 自分の世帯のメンバー | 自分 | 「選択できないメンバーです」 |
| メモ | — | 200 文字以内 | 空 | 「メモは 200 文字以内で入力してください」 |

### 3.2 世帯・プロフィール

| 項目 | 必須 | 制約 | 既定値 |
| --- | --- | --- | --- |
| 世帯名 | ○ | 1〜30 文字 | `わが家` |
| 表示名 | ○ | 1〜20 文字 | メールアドレスの `@` より前 |
| 招待コード（入力時） | ○ | 6 文字の英数字。小文字は大文字に変換して照合 | — |
| カテゴリ名 | ○ | 1〜20 文字。同一世帯・同一種別で重複不可 | — |

## 4. 受入条件

実装が終わったかの判定に使う。すべて**実際にブラウザで操作して**確認する（[テスト戦略](../03-guidelines/testing-strategy.md)）。

### AC-1 新規登録とログインができる（FR-A1〜A4）

- **前提**: 未ログイン状態で `/` を開く
- **操作 1**: `/login` に飛ばされる → 「アカウントを作る」 → メールアドレスと パスワード（+ 確認）を入力 → 「アカウントを作る」
- **期待 1**: 「確認メールを送りました」が表示される。メールのリンクを開くと `/setup`（または `/`）が開く
- **操作 2**: ログアウト → `/login` でメールアドレスとパスワードを入力 → 「ログイン」
- **期待 2**: **メールを使わずに**ログインが完了する
- **再確認**: ブラウザを閉じて開き直してもログインしたまま
- **失敗時**: パスワードを間違えると「メールアドレスまたはパスワードが正しくありません」が出る（どちらが違うかは示さない）

### AC-1b パスワードを忘れたときに入れる（FR-A6）

- **操作**: `/login` → 「ログインリンクを受け取る」 → メールアドレスを入力 → 送信
- **期待**: 「ログイン用のリンクを送りました」が表示される。メールのリンクを開くとログインできる
- **確認**: 未登録のメールアドレスでも同じ表示になる（登録済みかを漏らさない）

### AC-2 世帯を作れる（FR-H1, FR-H2）

- **前提**: ログイン済み、世帯未所属
- **操作**: `/setup` で名前と世帯名を入力 → 「家計簿を作る」
- **期待**: `/` に遷移する。`/settings` に招待コードが表示される。`/new` のカテゴリ選択に初期カテゴリ 13 件（支出）が出る

### AC-3 家族が参加できる（FR-H1, FR-H3）

- **前提**: 別のメールアドレスでログインした 2 つ目のアカウント、世帯未所属
- **操作**: `/setup` で 1 つ目の世帯の招待コードを入力 → 「参加する」
- **期待**: `/` に遷移し、1 つ目のアカウントが入れた記録が一覧に表示される。`/settings` のメンバー一覧に 2 名が並ぶ

### AC-4 記録を登録できる（FR-T1〜T6）

- **前提**: ログイン済み、世帯所属済み
- **操作**: 「記録する」→ 金額に `1280` → カテゴリ「食費」→「保存する」
- **期待**: `/` に戻り、今日の日付のグループに `食費 ¥1,280` が表示される。支出合計が 1,280 円増える
- **既定値の確認**: 種別は「支出」、日付は今日、支払った人は自分になっている
- **所要**: 起動から保存まで 10 秒以内、タップ 5 回以内

### AC-5 金額の検証が効く（FR-T2, BR-2）

- **操作**: 金額を空 / `0` / `-100` / `12.5` にして保存を試す
- **期待**: いずれも保存されず、金額の下にエラーが出る。入力した他の項目は消えない

### AC-6 編集・削除できる（FR-T7, FR-T8）

- **操作**: 一覧の行をタップ → 金額を `1500` に変更 → 「更新する」
- **期待**: 一覧に `¥1,500` として反映され、合計も変わる
- **操作**: もう一度開いて「この記録を削除」→ 確認で「削除する」
- **期待**: 一覧から消え、合計も変わる

### AC-7 月の移動と集計が正しい（FR-L1〜L4）

- **前提**: 当月と前月に記録がある
- **操作**: `‹` をタップ
- **期待**: 見出しが前月になり、URL が `/?m=YYYY-MM` に変わる。表示される記録が前月のものだけになる
- **検算**: 支出合計・収入合計が手計算と一致し、差額 = 収入 − 支出 になっている
- **再確認**: その URL をリロードしても同じ月が開く。ブラウザの戻るで当月に戻る

### AC-8 空の月の表示（FR-L6）

- **操作**: 記録のない月に移動する
- **期待**: 「まだ記録がありません」と「記録する」への導線が出る。合計はすべて 0 と表示される

### AC-9 他世帯のデータが見えない（FR-X2, BR-12）★最重要

- **前提**: アカウント A が世帯 A に記録を 1 件持つ。アカウント B は**別の世帯 B** を作る（A の招待コードは使わない）
- **操作 1**: B でログインして `/` を開く
- **期待 1**: A の記録が 1 件も表示されない。合計がすべて 0
- **操作 2**: B のセッションで `/transactions/<A の記録の ID>` を直接開く
- **期待 2**: 記録が表示されない（404 相当の表示になる）
- **操作 3**: B のセッションから A の記録に対する更新・削除を試みる
- **期待 3**: いずれも失敗する
- **自動テスト**: 同じ内容を DAL の単体テストでも検証する（[セキュリティガイドライン §4.3](../03-guidelines/security-guidelines.md#43-約束-c-dal-の認可を自動テストで守る)）

手順の詳細 → [テスト戦略 §4](../03-guidelines/testing-strategy.md)

### AC-10 カテゴリの非表示（FR-C5, FR-C6）

- **操作**: `/settings` でカテゴリ「交際費」を非表示にする
- **期待**: `/new` の選択肢から消える。「交際費」が付いた既存の記録は一覧でそのまま「交際費」と表示される

### AC-11 セットアップ前の振り分け（FR-X1）

- **前提**: ログイン済み、世帯未所属
- **操作**: `/`、`/new`、`/settings` をそれぞれ直接開く
- **期待**: すべて `/setup` に遷移する

### AC-12 スマホで使える（FR-X3）

- **前提**: 幅 375px（デバイスモードまたは実機）
- **期待**: 横スクロールが発生しない。下部タブで 3 画面を行き来できる。タップ対象が 44px 以上ある。OS をダークモードにすると配色が追従する
