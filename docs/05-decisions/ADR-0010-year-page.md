## 背景

本人の指摘。

> 現状は月の表示によって、だけみることができていているが、
> 比較をしたりすることができないのでできるようにしたい。

これに対し、まずスコープ判断の要らない**先月比**（FR-L9）を実装した。
続けて「複数月を並べる比較」をどうするか 3 案を出したところ、本人から
より具体的な形が示された。

> 例えば、2026年のページがあって、全ての月はこのような感じと
> ページで見れるようにしたい。

**これは [ADR-0009](./ADR-0009-desktop-layout-and-category-breakdown.md) で
保留した「月次の推移」そのもの。** プロダクト概要 §5.2 に
「月次の推移グラフ | 内訳（下記）が実際に役立つか見てから判断する」として
残していた項目なので、この ADR で記録する。

### 保留を解く理由

ADR-0009 では「内訳が実際に役立つか見てから」としていた。
**本人が具体的な形（年のページ）を指定したことで、判断の材料が変わった。**

- 「比較できない」という不満が実際に出た（推測ではない）
- 求められているのは**グラフというより一覧**。12 か月の数字が並び、
  そこから各月に飛べれば足りる
- 棒は数字の大小を掴むための補助で、主役ではない

## 決定

### 1. `/year/[year]` を作る

| 事項 | 決定 |
| --- | --- |
| URL | `/year/2026`。`/year` は**今年へリダイレクト**（ナビゲーションのリンク先を固定できるようにするため） |
| 不正な年 | `/year/abc` や `/year/99999` は**今年として扱う**（`?m=abc` と同じ方針。AC-7） |
| 年の範囲 | 2000〜2100。URL に巨大な数を入れられても 12 か月ぶん以上は引かない |
| 年の移動 | 見出しの左右に `‹` `›`。先の年・過去の年に制限を付けない（月の移動と同じ方針） |

### 2. 12 か月を必ず並べる

**記録が無い月も行として出し、「記録なし」と表示する。**

抜くと「1 月 → 3 月」のように詰まり、**使っていない月なのか記録を
忘れた月なのかが区別できない。** 家計簿は「記録が途切れていないか」を
自分で確認したいものなので、空白が見えること自体に意味がある。

| 1 行に出すもの | スマホ | PC |
| --- | --- | --- |
| 月 | ○ | ○ |
| 支出の額 | ○ | ○ |
| 支出の棒（相対） | ○ | ○ |
| 収入 | — | ○ |
| 差額 | — | ○ |

**棒の長さは「支出が最も多い月」を基準にした相対値。** この画面の目的は
月どうしの大小を掴むことなので、絶対額ではなく相対で見せる。

各行はその月のホーム（`/?m=2026-01`）へのリンク。**比較 → 詳細**の
流れで動けるようにする。

### 3. 年間のカテゴリ別内訳も出す（PC のみ）

[ADR-0009](./ADR-0009-desktop-layout-and-category-breakdown.md) で作った
`CategoryBreakdown` をそのまま使う。期間が月から年に変わるだけで、
コンポーネントは変更しない。

スマホに出さない理由は ADR-0009 と同じ（縦に伸びて月別一覧が押し出される）。

### 4. 集計は SQL で行わない

| | SQL で集計する | 行を取って純関数で集計（採用） |
| --- | --- | --- |
| 必要なもの | `date_trunc` を使う生 SQL（`$queryRaw`） | `findMany` 1 本 |
| 認可を書き忘れうる場所 | +1 | +1（どちらも DAL 関数 1 つ） |
| テスト | DB 必須 | **月の振り分けは DB 不要で試せる** |
| 禁止事項との関係 | 生 SQL は避けたい（coding-standards §11） | — |

`listTransactionsByYear(year)` でその年の行を取り、`summarizeYear()`
（純関数）が月に振り分ける。**1 年の件数は家族の家計簿なら数百件**なので、
行ごと取っても軽い。

月の振り分けは `monthOf`（**UTC**）で行う。`@db.Date` は UTC 0 時で返るため
（→ [DB設計 §5.2](../02-design/database-design.md#52-dbdate-の読み出しに注意)）。

### 5. ナビゲーションに「年」を足す

| 場所 | 表記 |
| --- | --- |
| サイドバー（PC） | 「年の一覧」。項目は 5 つになる |
| 下部タブ（スマホ） | 「年」。タブは 4 つになる |
| ホームの月見出し | `2026年11月` 自体を `/year/2026` へのリンクにする |

月見出しからのリンクが主な導線。**「この月を見ていて、他の月と比べたい」と
思った場所から 1 タップで行ける**のが自然。

### 煙テストが実行時エラーを 1 件捕まえた

ナビゲーションの現在地判定を、年のページ用に前方一致（`startsWith`）へ
変えたところ、`usePathname()` が **null を返す文脈で落ちた。**

Next.js の型は `usePathname(): string` だが、**App Router の文脈の外
（`react-dom/server` での単体描画）では実行時に null が返る。**
`?? ""` で受けるようにした。

[ADR-0009](./ADR-0009-desktop-layout-and-category-breakdown.md) の直前に
入れた煙テスト（[テスト戦略 §3.2.1](../03-guidelines/testing-strategy.md#321-画面部品の煙テスト)）が
効いた 2 件目。

## 見直す条件

| 条件 | 対応 |
| --- | --- |
| 1 年の件数が増えて重くなった | SQL での集計（`groupBy` + `date_trunc`）に替える。目安は 1 年 5,000 件 |
| 任意の 2 か月を細かく比べたくなった | 比較専用画面（`/compare?a=...&b=...`）を検討する。年のページで足りるか先に確かめる |
| 複数年をまたいで見たくなった | 年の一覧（`/year`）に年ごとの合計を並べる |
| スマホでも年間の内訳を見たくなった | 別画面として足す。年のページに積まない |

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 推移グラフだけをホームの右カラムに置く（ADR-0009 の案 B） | **本人の要望は「ページ」だった。** ホームに積むと縦に伸び、一覧が押し出される |
| 比較専用画面（2 か月を選んで並べる。案 E） | 選ぶ操作が増える。年のページなら全月が見えて、そこから詳細に飛べる |
| 記録が無い月を行から省く | 「使っていない月」と「記録を忘れた月」が区別できなくなる |
| 棒の長さを絶対額（固定の最大値）で決める | 月の大小が掴めない。月どうしの比較がこの画面の目的 |
| SQL で月別に集計する（`date_trunc`） | 生 SQL を避けたい（coding-standards §11）。件数が少なく、純関数のほうがテストしやすい |
| 棒グラフを縦にする（月を横軸） | スマホ幅で 12 本並べると 1 本 25px 未満になり、金額のラベルが置けない |
| グラフのライブラリを入れる | 横棒は `div` 2 つで描ける。[ADR-0009](./ADR-0009-desktop-layout-and-category-breakdown.md) の判断を維持 |
