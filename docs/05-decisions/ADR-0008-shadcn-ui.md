## 背景

M3（記録と一覧）までを Tailwind のユーティリティだけで組んだ。動くが、開発者から
**「少しシンプルすぎる。もっとリッチにしてほしい」** という評価を受けた。

自前のスタイルを積み増しても良いが、以下が自前では割に合わない。

| 自前だと重いもの | 具体例 |
| --- | --- |
| 開閉・重ね合わせの挙動 | 折りたたみ、ポップオーバー、ダイアログのフォーカス管理 |
| 状態の網羅 | hover / focus-visible / disabled / aria-invalid / ダークの組み合わせ |
| 一貫性 | 角丸・余白・影・リングの値が画面ごとに少しずつずれる |

**依存を増やす判断なので ADR を書く**（NFR-M7）。

## 決定

**shadcn/ui を Radix ベース（プリセット `nova`）で採用する。**

| | |
| --- | --- |
| ベース | **Radix UI**（RC の Base UI を避ける。[ADR-0007](./ADR-0007-better-auth.md) で Auth.js v5 を却下したのと同じ理由） |
| プリセット | `radix-nova` |
| アイコン | lucide |
| 置き場所 | `src/components/ui/`（**生成されたコードはこのリポジトリのもの**。npm の依存ではない） |

shadcn/ui は**ライブラリではなくコード生成**である。`src/components/ui/*.tsx` は
生成後は自分のコードなので、遠慮なく編集する。

### 採用にあたって shadcn の既定から変えた点

| 変えたもの | 既定 | このプロジェクト | 理由 |
| --- | --- | --- | --- |
| `Button` の `default` の高さ | `h-8`（32px） | **`h-11`（44px）** | **NFR-U7**。スマホで片手操作する前提 |
| `Button` の `lg` | `h-9` | **`h-12`**（角丸 `xl`） | 画面下の主ボタン。親指で押す |
| `Button` の `icon` / `icon-lg` | `size-8` / `size-9` | **`size-11` / `size-12`** | 同上 |
| `Input` の高さ | `h-8` | **`h-11`** | 同上。文字は 16px のまま（iOS が 16px 未満の入力欄で画面を拡大するため下げられない） |
| ダークモードの判定 | `.dark` クラス（next-themes 前提） | **`@custom-variant dark` を `data-theme` 属性に繋ぐ** | 既存の `color-scheme` + `light-dark()` の仕組みを維持する |
| 単一選択の切り替え | `ToggleGroup`（Radix） | **`SegmentedControl`（中身は本物の `<input type="radio">`）** | Radix の ToggleGroup は単一選択でも role が group。radio なら矢印キーと読み上げが標準で効く |
| 「支払った人」の選択 | `Select`（Radix） | **ネイティブの `<select>`** | スマホでは OS 標準のピッカーのほうが速く確実。生成した `select.tsx` は削除した |

### デザイントークンの扱い

**命名を shadcn に合わせ、値の指定方法は従来のまま**にした。

| | 変更前 | 変更後 |
| --- | --- | --- |
| 命名 | `--surface` / `--muted` / `--danger` / `--accent` | **`--card` / `--muted-foreground` / `--destructive` / `--primary`** |
| 値の書き方 | `light-dark()` 1 箇所 | **変更なし** |
| 切り替え | `color-scheme` | **変更なし** |

命名を寄せたのは、**今後コンポーネントを追加したときにそのまま馴染むため**。
値の書き方を寄せなかったのは、`.dark` クラス方式では定義が二重化し、
スクロールバーや `<input type="date">` などのネイティブ UI が追従しないため。

旧 `--muted` / `--accent` は shadcn と**意味が逆だった**（旧 `--muted` は補助テキストの色、
shadcn の `--muted` は背景色）。移行時にここを取り違えると配色が崩れるので、
旧トークンは**残さず削除した**（残すと片方だけ直す事故が起きる）。

### Monely 固有のトークン

| トークン | 用途 | なぜ shadcn のもので済まないか |
| --- | --- | --- |
| `--income` | 収入の金額、成功の通知 | shadcn に「プラスの意味」の色が無い |
| `--deficit` | 差額がマイナスのときの金額 | `--destructive` と**役割が違う**（お金の色 / 破壊的な操作の色）。削除ボタンの赤を調整したときに金額の色まで動かないよう分けた |

支出は中立色（`--foreground`）のまま。毎日のことなので、赤にすると一覧が警告だらけになる。

## コントラストの検証を機械化した

色を 10 個以上入れ替えたので、目で確かめるのをやめて
**`scripts/check-contrast.mjs`（`pnpm check:contrast`）** を書いた。
`globals.css` の `light-dark()` を読み、oklch → sRGB に変換して、
文字色と背景色の 14 組をライト / ダークの両方で判定する（WCAG AA = 4.5:1、NFR-U6）。

**実際に 2 件落ちた。** 目視では気づけなかった。

| 落ちた組み合わせ | 比率 | 直し方 |
| --- | --- | --- |
| ダークの主要ボタンの白文字 | 4.26:1 | `--primary` の明度を 0.588 → **0.555** に下げた（4.91:1） |
| ダークの破壊的ボタンの白文字 | 3.01:1 | 下記 |

破壊的ボタンは単純な調整では直らなかった。**`--destructive` を暗くすると白文字は読めるが、
nova プリセットの `Button` は destructive を「薄い地色 + destructive の文字」で描く**ため、
今度はその文字がカード上で 3.27:1 になる。1 つのトークンで
「文字として読める明るさ」と「白文字を載せられる暗さ」は両立しない。

→ **`--destructive` は文字として読める明るさに保ち、`--destructive-foreground` を
モードごとに反転させた**（ライト = 白、ダーク = ほぼ黒）。これで地色として塗られても 6.29:1。

## 見直す条件

| 条件 | 対応 |
| --- | --- |
| Base UI が安定版になり、採用が広がった | 移行は検討しない。生成済みのコードは自分のもので、ベースを替える利得が無い |
| ダイアログやトーストが必要になった | `pnpm dlx shadcn add dialog` などで追加する。**追加のたびに ADR は要らない**（新しい npm 依存が増える場合のみ書く） |
| `cn` パッケージの更新が止まった | 10 行程度の関数なので `src/lib/utils.ts` に直接書けば依存を外せる |
| Tailwind v5 が出た | `@theme inline` と `@custom-variant` の書式変更に追従する |

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| **Base UI ベース**（shadcn の新しい既定） | **1.0.0-rc.0 のまま 4 か月更新が止まっている。** 週間 DL も Radix の 1/28。[ADR-0007](./ADR-0007-better-auth.md) で Auth.js v5 を却下した基準をそのまま適用した |
| React Aria ベース | a11y は最も厚いが、DL は Radix の 1/3 で、shadcn のプリセットも Radix 前提のものが多い |
| MUI / Mantine / Chakra | **ランタイムのライブラリとして依存する**ことになる。shadcn はコードを生成して終わりなので、後から中身を直せる。スマホ向けに高さを 44px に変えたような改変が自由にできる |
| 自前で組み続ける | 折りたたみのフォーカス管理や状態の網羅を自分で持つことになる。今回の「リッチにする」要望に対して時間の使い方が悪い |
| `--muted` / `--accent` の旧い意味を残したまま shadcn を入れる | 同じ名前が 2 つの意味を持つ。生成されたコンポーネントが期待する色と逆になり、見つけにくい崩れを生む |
| コントラストを目視で確認する | **実際に 2 件見逃していた。** oklch の明度は見た目と比率が一致しない |
