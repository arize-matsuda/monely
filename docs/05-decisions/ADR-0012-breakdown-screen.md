| | |

| **決定者** | 開発者本人 |

## 背景

本番で動き始めたあと、本人から質問があった。

> 現在、日にちごとにみることはできるのですが、月単位でそれぞれの
> カテゴリーごとにどのくらい使われているか。みたいなのをみることはできますか？

**機能としては既にあった**（FR-L8、[ADR-0009](./ADR-0009-desktop-layout-and-category-breakdown.md)）。
ただしホームの右カラムに置いてあり、**`md`（768px）未満では表示していなかった。**

ADR-0009 でスマホに出さなかった理由はこうだった。

> カテゴリが 13 個あると縦に伸び、**一覧（この画面の主役）が下に押し出される。**
> 必要になったら別画面として足す（v2）。

**この「必要になったら」に当たった。** 続けて「PC とスマホで見れるように
してほしい」という要望を受けた。

---

## 決定

### 1. `/breakdown` を作る（画面を増やす）

| 事項 | 決定 |
| --- | --- |
| URL | `/breakdown?m=2026-11`。月の指定は `?m=` でホームと揃える |
| 表示する幅 | **スマホと PC の両方。** 専用画面なので一覧と場所を争わない |
| 不正な月 | 当月として扱う（`parseMonth`。AC-7 と同じ方針） |
| 月の移動 | `MonthSwitcher` を再利用。**遷移先を `basePath` で差し替えられるようにした** |
| 年へのリンク | この画面では出さない（月の内訳を見ている最中に年へ飛ばす導線は要らない） |
| ホームの右カラム | **そのまま残す。** PC では一覧と並べて見えるほうが速い |

**ホームの表示を削らない。** 専用画面を足しても、PC で横に見える利点は
失われていない。同じコンポーネント（`CategoryBreakdown`）を両方で使う。

### 2. カテゴリから記録へ辿れるようにする（FR-L13）

内訳の行をタップすると `?c=<カテゴリID>` が付き、**その月のそのカテゴリの
記録だけ**を日付ごとに出す。

| 事項 | 決定 |
| --- | --- |
| 置き場所 | **同じ画面。** 別ルートにすると「内訳に戻る」が履歴頼みになる |
| 出すもの | カテゴリ名・件数・合計・予算の消化率 ＋ 記録の一覧（`TransactionList` を再利用） |
| URL の検証 | **その月に実在するカテゴリだけ受け付ける。** 一致しなければ内訳を出す |
| 導線 | ホームの右カラムの内訳からも同じ画面に飛ぶ |

#### なぜ「絞り込み」を v1 外から持ち込むのか

[UI/UX設計](../02-design/ui-ux-design.md) §10 では「検索・絞り込み」を
落としていた（理由: 月の移動で足りる）。**いま作ったのは検索ではなく、
内訳からの 1 タップの導線**で、入力も選択 UI も要らない。

「内訳を見て終わり」では行動が変わらない。**「食費が 42% だった」の次に
「何に使ったのか」**が見えて初めて次の判断ができる。

#### 行をリンクにする実装

内訳は `dl` / `dt` / `dd` で組んでいる（名前と金額の対応を読み上げに
伝えるため）。**外側を `Link` で包むとこの構造が崩れる**ので、
行全体を覆う透明なリンクを `absolute inset-0` で重ねた。
棒や割合もタップ対象になり、読み上げの構造も保たれる。

### 3. 下部タブは 5 つにする

| | スマホ（下部タブ） | PC（サイドバー） |
| --- | --- | --- |
| 項目 | ホーム / **記録** / **内訳** / 年 / 設定 | ホーム / 記録する / **内訳** / 年の一覧 / カテゴリ / 設定 |

**375px で 1 タブ 75px** になるため、スマホのラベルを「記録する」→「記録」に
縮めた。サイドバーは幅に余裕があるので「記録する」のまま。

### 4. DB のクエリは増やさない

絞り込みは**取得済みの行から**行う（`rows.filter`）。
カテゴリで絞る DAL 関数を足すと `householdId` の条件を書き忘れうる場所が
1 つ増える（[ADR-0005](./ADR-0005-authorization-in-app-layer.md) の約束 B）。
1 か月の件数は家族の家計簿なら数十件なので、絞ってから引く必要が無い。

## 見直す条件

| 条件 | 対応 |
| --- | --- |
| カテゴリ以外（支払った人・メモ）でも絞りたくなった | 絞り込みの軸を増やす。URL のパラメータを足す形で広げられる |
| 内訳の対象期間を月以外にしたくなった | 年のページの内訳も同じ画面に寄せる（いまは年のページ内に別に置いている） |
| 件数が増えて `rows.filter` が重くなった | DAL にカテゴリ条件つきの関数を足す。目安は 1 か月 1,000 件 |
| スマホでホームにも内訳を出したくなった | ADR-0009 の判断（一覧が押し出される）を再検討する。いまは専用画面で足りる |

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| ホームのスマホ表示に内訳を出す | [ADR-0009](./ADR-0009-desktop-layout-and-category-breakdown.md) の判断どおり、カテゴリ 13 個で一覧が下に押し出される |
| ホームの右カラムから内訳を外し、専用画面だけにする | PC では一覧と並べて見えるほうが速い。削る理由が無い |
| 絞り込みを別ルート（`/breakdown/[categoryId]`）にする | 「内訳に戻る」がブラウザの履歴頼みになる。同じ画面なら戻り先が明示できる |
| 絞り込み用の DAL 関数を足す | 認可を書き忘れうる場所が増える。件数が少なく、取得済みの行で足りる |
| 行の外側を `Link` で包む | `dl` / `dt` / `dd` の構造が崩れ、名前と金額の対応が読み上げに伝わらなくなる |
| タブを増やさずメニューに入れる | 階層が深くなる。5 つは 375px に収まる |
